# Безопасность CodeBloodhound

Проверка кода и тестов от 21 ноября 2026 года. Прототип предназначен для синтетических учебных проектов.

| Область | Что защищено | Что остаётся |
| --- | --- | --- |
| Доступ к демо | HTTPS-прокси проверяет общий пароль или приглашение. Отдельная учётная запись в приложении защищает личные сценарии, архивы, отчёты и настройки языковых плагинов. Пароли приложений хэшируются через scrypt с солью. Срок сессии составляет семь дней, выход отзывает её на сервере. | Старые и гостевые сценарии и архивы доступны в общем пространстве. Каталог сохранённых нод общий. Роли и сброс пароля пока отсутствуют. Смена общего пароля прокси отзывает все приглашения и его cookie. |
| ZIP и репозитории | Код проекта читается статически из ZIP, без запуска Gradle или исходников. Проверяются размер файла, суммарный размер, число записей, пути, дубликаты, симлинки, шифрование и CRC. Для публичных репозиториев GitHub бэкенд сам строит URL для `codeload.github.com`, блокирует редиректы, ограничивает размер и время скачивания. | ZIP-загрузку и импорт по ссылке для рабочего пространства нужно использовать только с учебными проектами. |
| Хранение и секреты | Детектор секретов сохраняет тип, файл и строку без найденного значения. Ключи LLM и адреса webhook передаются серверу через его конфигурацию. | Загруженные ZIP и отчёты хранятся в PostgreSQL без шифрования на уровне приложения. Политики удаления и Vault отсутствуют. Если секрет записан в имени файла, путь сам может содержать чувствительные данные. |
| AI и внешний трафик | Ключ провайдера остаётся на сервере, DeepSeek требует согласия в API. Модель получает данные о находках, а пути фильтруются перед запросом. Ссылки карточек берутся из отчёта. Валидатор сверяет явные CVE, GHSA и ссылки вида `файл:строка`. При повторном некорректном ответе карточки строятся по правилам сканеров, а чат убирает недостоверный ответ. | Фильтр не проверяет истинность всех текстовых утверждений модели. При использовании внешней модели и публичных туннелей передавать только разрешённые учебные данные. |
| Уведомления | Адрес webhook, токен бота и чат Telegram задаёт оператор на сервере. Через ноду выбирается имя получателя. Редиректы выключены, задан таймаут. Webhook получает находки и AI-результаты активной ветки, Telegram получает ID запуска и число находок по критичности. | Webhook не подписывается. Произвольные HTTP(S)-адреса допустимы для оператора, включая локальные приёмники. Для внешнего получателя нужен HTTPS и проверенная конфигурация назначения. |

Языковые плагины состоят из встроенных статических правил. Настройка источника ограничена относительным путём внутри уже загруженного ZIP. Путь, которого в архиве нет, останавливает связанные проверки.

Пользовательские плагины хранят настройки кастомной ноды. Сервер принимает только параметры редактора и встроенные проверки. Плагины не запускают пользовательские скрипты или команды. База ограничивает чтение приватных плагинов владельцем, а редактирование и удаление любого плагина проверяют владельца. Ноды, добавленные как приватные, сохраняются только в личном сценарии и блокируют его публикацию. Изменение видимости ограничивает новые обращения к плагину, а ранее добавленные копии продолжают работать.

Общая библиотека сценариев хранит отдельную опубликованную копию графа. Сервер разрешает публикацию владельцу личного сценария, исключает привязки ZIP и webhook, заметки и список плагинов. Пути и условия остаются частью публичного шаблона. Снятие с публикации не удаляет оригинал и уже сделанные пользователями копии.

Ежедневный запуск работает с закреплённым учебным ZIP. Если DeepSeek выбран моделью по умолчанию, сервер всё равно требует явного согласия на каждый ручной запрос. В автоматическом запуске находки остаются в отчёте с подсказками по правилам сканеров. Условия с регулярным выражением проверяют только метаданные находок и выполняются через RE2.
